# Requirements: Aria

**Defined:** 2026-03-18
**Core Value:** Students never miss a deadline or lose track of their week — Aria surfaces what matters, when it matters, over SMS and iOS.
**Last updated:** 2026-03-19 — PRD v1.1 alignment (9-phase roadmap, iOS app, Priority Engine, scope promotions)

## v1 Requirements

### Authentication & Onboarding

- [x] **AUTH-01**: User can create an account with email and password via Supabase Auth
- [ ] **AUTH-02**: User can connect Google account via OAuth 2.0 (Calendar + Gmail scopes)
- [ ] **AUTH-03**: Google OAuth tokens stored encrypted (AES-256) in Supabase with refresh rotation
- [x] **AUTH-04**: User session persists across browser refresh
- [ ] **AUTH-05**: User can enter Canvas iCal URL during onboarding (validated before saving)
- [ ] **AUTH-06**: User can enter phone number during onboarding and verify via SMS PIN
- [x] **AUTH-07**: User receives a welcome briefing immediately after Canvas iCal URL is saved (cold-start prevention)

### Canvas Integration

- [x] **CANV-01**: System fetches user's Canvas iCal feed and parses VEVENT records into Task type
- [x] **CANV-02**: Parsed Canvas deadlines stored in Supabase `deadlines` table with `synced_at`
- [x] **CANV-03**: Canvas iCal feed synced every 60 minutes via background job
- [x] **CANV-04**: Diff engine detects added, changed, and removed deadlines between syncs
- [x] **CANV-05**: Canvas API rate limits handled with exponential backoff (max 120 req/min)

### Gmail Integration

- [ ] **GMAI-01**: System monitors Gmail for emails from course-related senders
- [ ] **GMAI-02**: Keyword detection identifies deadline changes, cancellations, and exam updates in emails
- [ ] **GMAI-03**: Parsed Gmail signals stored in `gmail_flags` table (metadata only — subject, sender, flagged_at, summary; full email content never stored permanently)
- [ ] **GMAI-04**: Gmail watch channel renewed automatically before 7-day expiry
- [ ] **GMAI-05**: Gmail signals cross-referenced against Canvas state to detect contradictions

### Google Calendar Integration

- [ ] **GCAL-01**: System fetches user's Google Calendar events (7-day rolling window) via OAuth
- [ ] **GCAL-02**: Calendar events normalized to CalendarEvent type and stored in Supabase
- [ ] **GCAL-03**: GCal push notification channel established for real-time change detection
- [ ] **GCAL-04**: GCal push channel renewed automatically before 7-day expiry
- [ ] **GCAL-05**: User can request study blocks written to their Google Calendar via SMS

### SMS Interface

- [x] **SMS-01**: System can send outbound SMS to user via Twilio
- [x] **SMS-02**: Twilio inbound webhook returns 200 immediately and enqueues processing to Celery (never inline)
- [x] **SMS-03**: Inbound SMS routed to Claude Sonnet for conversational reply
- [x] **SMS-04**: Maximum 3 unsolicited SMS per day per user enforced
- [x] **SMS-05**: Quiet hours enforced (no SMS between 10pm–8am in user's timezone)
- [x] **SMS-06**: STOP command immediately opts user out and confirms with final SMS
- [x] **SMS-07**: PAUSE command suspends SMS for 24 hours
- [x] **SMS-08**: HELP command replies with list of commands
- [x] **SMS-09**: Opt-out status checked before every outbound SMS regardless of carrier-level blocking
- [ ] **SMS-10**: Multiple alerts firing within 10 minutes are batched into a single SMS
- [ ] **SMS-11**: No more than 3 texts sent in any 10-minute window regardless of trigger source

### Conversational AI

- [x] **CONV-01**: Last 5 SMS exchanges included as conversation history in Claude context for all conversational replies

### AI Layer

- [ ] **AI-01**: User can upload syllabus PDF via web UI
- [ ] **AI-02**: Claude Opus parses syllabus PDF and extracts exams, assignments, topics, and grade weights
- [ ] **AI-03**: Parsed syllabus data stored as structured JSON in Supabase `syllabi` table
- [x] **AI-04**: Daily briefing generated by Claude Sonnet using last 14 days of deadlines + 7 days of calendar + last 5 conversation exchanges
- [x] **AI-05**: Daily briefing SMS sent at 8am in user's local timezone
- [x] **AI-06**: Briefing generation job runs at 7am daily (1 hour before send)
- [x] **AI-07**: Conversational SMS replies generated by Claude Sonnet via Celery; supports deadline queries and task management (mark complete, snooze, set priority)
- [x] **AI-08**: Monday extended briefing covers full 7-day deadline horizon; enriched with GCal conflicts and available study windows when GCal is connected (Phase 6)
- [x] **AI-09**: Daily load score (green / yellow / red) computed at briefing generation time based on deadline count, urgency, and grade weights
- [ ] **AI-10**: Study gap analysis generated at T-5 days before exam, cross-referencing syllabus topics against covered material
- [x] **AI-11**: Exam day-of morning logistics message sent at 7am on the day of each exam

### Priority Engine

- [x] **PRIO-01**: Canonical Timeline DB stores all normalized events from all integrations in a unified schema with source, type, title, due_at, course_id, and grade_weight
- [x] **PRIO-02**: Priority Engine scores every event: `Priority = (grade_weight × 0.35) + (urgency × 0.45) + (source_authority × 0.20)` where Canvas = 1.0, professor email = 0.9, Todoist = 0.8, Discord = 0.6
- [x] **PRIO-03**: Delivery router: score ≥ 80 triggers immediate SMS; score 50–79 queues for next digest; score < 50 logged silently (visible in app only)

### Deadline Alerts

- [ ] **ALRT-01**: Deadline change alert fired within 15 minutes of Canvas diff detection
- [ ] **ALRT-02**: Gmail contradiction alert fired when professor email conflicts with Canvas deadline
- [ ] **ALRT-03**: Alert SMS includes original deadline, new deadline, course name, and assignment title

### Intelligence

- [ ] **INTEL-01**: Study gap detection — cross-reference syllabus topics with student's covered material; surface gaps before exams
- [ ] **INTEL-03**: Conflict detection — flag Canvas deadlines that overlap existing GCal events; offer resolution options via SMS

### Sync Engine

- [x] **SYNC-01**: Celery + Redis deployed on Railway for all background jobs
- [x] **SYNC-02**: Canvas iCal sync job runs every 60 minutes per user
- [ ] **SYNC-03**: GCal push notification handler processes calendar changes in real time
- [ ] **SYNC-04**: GCal and Gmail watch channels renewed via Celery Beat cron (48 hours before expiry)
- [x] **SYNC-05**: Daily briefing generation job runs at 7am per user timezone (Celery Beat)
- [x] **SYNC-06**: Exam countdown check job runs daily at 7am; fires touchpoints at T-7 (topics + study windows), T-5 (gap analysis stub → Phase 7 full), T-3 (midpoint check + office hours reminder), T-1 (final review), T-0 (day-of logistics message)

### Task Management

- [ ] **TASK-01**: Todoist OAuth connection and task read/write
- [ ] **TASK-02**: Todoist tasks normalized to Task type and included in briefings and scheduling priority

### Frontend UI

- [ ] **UI-01**: Onboarding flow — phone number entry, Canvas iCal URL, Google OAuth connect
- [ ] **UI-02**: Syllabus upload UI — file picker, upload progress, confirmation
- [ ] **UI-03**: Preferences page — quiet hours, notification frequency, connected integrations
- [ ] **UI-04**: Connection status page — shows linked Google/Canvas status with health indicators
- [ ] **UI-05**: First briefing preview — shows what user's first briefing will look like after onboarding

### iOS App

- [ ] **UI-06**: iOS app home screen with 4-zone layout: (1) pinned quick-access bar (To-Do, Calendar, Notifications), (2) color-coded daily load status bar, (3) scrollable widget card grid, (4) persistent chat + voice bar
- [ ] **UI-07**: In-app chat channel connected to same Aria backend as SMS; separate conversation thread; all SMS commands work in-app
- [ ] **UI-08**: Voice input via on-device speech recognition; transcribed to same Claude pipeline; optional text-to-speech read-back
- [ ] **UI-09**: Card customization — drag to reorder, swipe to hide, accent color, dark mode, tap to expand

## Out of Scope

| Feature | Reason |
|---------|--------|
| Grade/submission data access | FERPA violation — Canvas iCal only, never grades |
| Real-time Canvas webhooks | Institutionally impossible without admin credentials |
| Apple Health integration | iOS device-only, no server-side API |
| Native iMessage (no Sendblue) | No Apple API exists |
| Chroma vector DB | Replaced by pgvector (Supabase native, less complexity) |
| Android app | iOS only for v1; Android is Phase 3 or later |
| Canvas assignment submission | Write access to Canvas out of scope |
| AI tutoring / content explanation | Different product category |
| Non-US university platforms | Focus on US Canvas institutions first |
